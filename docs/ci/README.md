# Keeva Continuous Integration (CI)

This directory documents the Continuous Integration architecture, workflows, and automated verification pipeline for Keeva.

---

## 1. Overview & Purpose

Keeva uses GitHub Actions to automate source quality control, security auditing, and release build validation on every pull request and push to the default branch (`main`).

The CI pipeline guarantees that:
- Code adheres to strict formatting standards (`dart format`).
- Static analysis emits zero errors or warnings (`flutter analyze`).
- Unit and widget test suites pass (`flutter test` — 210 tests).
- Android JVM integration unit tests pass (`./gradlew test` — 7 tests).
- Production artifacts (`app-release.apk` and `app-release.aab`) remain 100% buildable without requiring production signing secrets.
- Strict privacy, licensing, and package identity invariants are never broken.

---

## 2. Workflow Triggers

The primary workflow (`.github/workflows/ci.yml`) is triggered on:
- **`pull_request`:** Any pull request targeting the `main` branch.
- **`push`:** Any direct push or merge into `main`.
- **`workflow_dispatch`:** Manual invocation from the GitHub Actions console for testing and maintainer inspection.

---

## 3. Pipeline Job Architecture

```text
GitHub Event (PR / Push / Dispatch)
   │
   ├── compliance       ──> Secret Leak + Manifest Privacy + Package ID + License + Version
   ├── formatting       ──> dart format check
   ├── analyze          ──> flutter analyze
   ├── flutter-tests    ──> flutter test (Unit + Widget suites)
   └── android-tests    ──> ./gradlew test (Kotlin JVM tests)
         │
         ▼ (Requires all 5 jobs to pass)
   release-build        ──> Build APK + AAB, Validate AAPT Badging & Privacy, Upload Artifacts
```

### 3.1 Job Breakdown

| Job ID | Name | Responsibility | Runtime Environment |
| :--- | :--- | :--- | :--- |
| `compliance` | Repository Compliance & Safety | Scans tracked files for credential leaks, verifies Apache-2.0 license, asserts `io.nishvanta.keeva` package identity, verifies syntax of `pubspec.yaml` version, and guarantees absence of `INTERNET` and `MANAGE_EXTERNAL_STORAGE` in source manifests. | `ubuntu-latest` |
| `formatting` | Code Formatting | Enforces project-wide Dart code styling via `dart format --output=none --set-exit-if-changed lib test integration_test`. | `ubuntu-latest` |
| `analyze` | Static Analysis | Executes `flutter analyze` against the entire codebase with zero tolerance for analyzer warnings or errors. | `ubuntu-latest` |
| `flutter-tests` | Flutter Unit & Widget Tests | Executes the comprehensive 210-test Flutter test suite (`flutter test`). | `ubuntu-latest` |
| `android-tests` | Android JVM Tests | Sets up Java 21 and Gradle 9.3.1 to execute Kotlin JVM unit tests (`cd android && ./gradlew test`). | `ubuntu-latest` |
| `release-build` | Release Build & Validation | Runs only if all preceding jobs succeed. Compiles release APK and AAB, verifies binary badging and permission exclusion using Android SDK `aapt`, and uploads build artifacts. | `ubuntu-latest` |

---

## 4. Release Build Validation & AAPT Inspection

To guarantee production readiness without human guesswork, `release-build` performs programmatic binary verification on `app-release.apk` using the Android SDK `aapt` tool:
1. **Package Identity:** Verifies `package: name='io.nishvanta.keeva'`.
2. **Application Label:** Verifies `application-label:'Keeva'`.
3. **Permission Safeguards:** Asserts that neither `android.permission.INTERNET` nor `android.permission.MANAGE_EXTERNAL_STORAGE` is present in the compiled APK.
4. **Bundle Verification:** Asserts that `app-release.aab` is generated, non-empty, and computes its SHA-256 checksum for audit trails.

---

## 5. Artifact Retention & Handling

Artifacts generated by `release-build` are intended for temporary pre-release inspection:
- **`app-release-apk`:** `build/app/outputs/flutter-apk/app-release.apk`
- **`app-release-aab`:** `build/app/outputs/bundle/release/app-release.aab`
- **Retention Period:** 3 days. Artifacts are automatically purged by GitHub to prevent unnecessary storage consumption.
- **Publishing Policy:** Artifacts are **never** automatically deployed to Google Play or published to GitHub Releases during Phase 3B.
