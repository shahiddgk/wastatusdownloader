WA STATUS DOWNLOADER
PROJECT INTEGRATION, STORAGE, BACKEND AND API REPORT
=====================================================

Audit date: 2026-09-18
Repository: Existing Flutter Android-first application

1. EXECUTIVE SUMMARY
--------------------
This application is a local-first Flutter app for discovering, previewing,
saving and sharing WhatsApp Status media.

The current project does NOT use:
- Firebase
- Firestore
- Firebase Storage
- Firebase Analytics
- Firebase Crashlytics
- Supabase
- REST APIs
- GraphQL APIs
- A custom backend server
- Cloud backup
- Remote media upload
- Third-party advertising or telemetry SDKs

The media workflow is performed on-device through Flutter, a Dart-to-Kotlin
MethodChannel, Android Storage Access Framework (SAF), Android ContentResolver,
Android MediaStore and local application cache directories.

2. FLUTTER ARCHITECTURE
-----------------------
The main layers are:

Presentation
- Screens for onboarding, Status/Moments, Saved/Kept Vault, Settings and viewer.
- Widgets render state and forward user actions.

Application
- Riverpod notifiers coordinate access, status list, saving and video viewer state.
- Theme preference is stored locally and exposed to MaterialApp through ThemeMode.

Domain
- Entities include status items, saved media and storage-access state.
- Use cases include checking/requesting storage access, loading statuses,
  generating thumbnails, preparing video playback, saving media and sharing media.

Data
- StatusRepositoryImpl coordinates the platform datasource.
- DTOs translate native MethodChannel maps into typed Dart domain entities.

Platform
- MethodChannelStatusScanner is the Dart boundary for native Android operations.
- Channel name: com.example.whatsapp_status_saver/scanner

Native Android
- MainActivity registers AndroidStatusScanner.
- AndroidStatusScanner dispatches heavy storage work to Kotlin coroutines on
  Dispatchers.IO and returns structured results/errors to Dart.

3. EXTERNAL APIs AND PLATFORM APIs
----------------------------------
There are no external internet APIs in the application.

Android platform APIs currently used:
- ACTION_OPEN_DOCUMENT_TREE
  Opens Android's system folder picker so the user selects a WhatsApp folder.
- Storage Access Framework / DocumentsContract
  Reads authorized document trees and creates files in a user-selected folder.
- ContentResolver
  Opens document streams, reads media and manages persisted URI permissions.
- DocumentFile / document-tree handling
  Validates and enumerates WhatsApp status documents.
- MediaStore
  Exports saved images to Pictures/SavedStatus and videos to Movies/SavedStatus
  when the user has not selected a custom destination folder.
- MediaMetadataRetriever
  Extracts video frames for thumbnails.
- Android BitmapFactory
  Decodes/downsamples image thumbnails.
- Android Intent.ACTION_SEND and FileProvider
  Shares saved/status media with other installed Android applications.
- SharedPreferences
  Stores small local preferences and native folder metadata.

Flutter/Dart packages relevant to runtime behavior:
- flutter_riverpod: state management.
- video_player: video playback.
- shared_preferences: local Flutter preferences such as theme mode.
- google_fonts: typography support.
- cupertino_icons: icon package.

No HTTP client package is present in pubspec.yaml and no network request layer
was found in the application code.

4. WHATSAPP STATUS DISCOVERY FLOW
---------------------------------
1. User selects WhatsApp or WhatsApp Business.
2. Flutter calls checkFolderAccess/requestFolderAccess over MethodChannel.
3. Android launches ACTION_OPEN_DOCUMENT_TREE.
4. User grants access to the selected folder.
5. Android persists the URI permission in the native storage layer.
6. SafStorageManager validates the selected tree and resolves the .Statuses
   directory/document ID.
7. StatusDocumentReader enumerates image/video documents through ContentResolver.
8. Android returns metadata maps to Dart.
9. StatusRepositoryImpl maps DTOs to StatusItem domain objects.
10. The Status screen displays the items.

Supported target packages are:
- com.whatsapp
- com.whatsapp.w4b (WhatsApp Business)

5. SAVING AND BACKUP BEHAVIOR
-----------------------------
There is no cloud backup in the current project.

Saved media is stored locally in one of two ways:

A. User-selected destination
- Settings can launch ACTION_OPEN_DOCUMENT_TREE for a destination folder.
- The selected destination URI and display name are stored in native
  SharedPreferences file: keeva_storage_prefs.
- MediaStoreSaver creates a document in that selected folder using
  DocumentsContract.createDocument and copies the media bytes locally.

B. Default Android public collections
If no destination folder is selected:
- Images are saved through MediaStore Images collection under:
  Pictures/SavedStatus/
- Videos are saved through MediaStore Video collection under:
  Movies/SavedStatus/
- Android 10+ scoped-storage pending/finalization behavior is used.
- Failed MediaStore writes are rolled back by deleting the incomplete row.

This is local device storage, not a server backup. The files are visible to the
user through the device gallery/file manager according to Android storage rules.

6. LOCAL PERSISTENCE
--------------------
Native SharedPreferences:
- keeva_storage_prefs
- Stores selected download folder URI and display name.
- Stores native saved-status flags/metadata used by the Android layer.

Flutter SharedPreferences:
- theme_mode stores system/light/dark selection.

Native cache directories:
- context.cacheDir/thumbnails
  ThumbnailManager stores downsampled WebP/JPEG thumbnails.
  Maximum target cache: 100 MB; pruning target: 80 MB.
- context.cacheDir/videos
  VideoCacheManager stores temporary playback MP4 copies.
  Maximum target cache: 100 MB; pruning target: 75 MB.

These cache files are temporary application caches, not backups. Android may
clear cache directories when needed. The clearCaches operation removes cache
files but does not delete saved Gallery/MediaStore media.

7. BACKEND STATUS
-----------------
There is no backend server in this repository.

No user account, login, token, API key, remote database, cloud bucket, remote
sync job, or background upload worker was found. All processing is designed to
remain on the device.

8. FIREBASE STATUS
------------------
Firebase has no role in the current implementation.

Evidence from the current project configuration/code:
- No Firebase package appears in pubspec.yaml.
- No google-services.json or GoogleService-Info.plist integration is used for
  Firebase services.
- No Firebase initialization call exists in Dart or Android code.
- No Firestore, Firebase Storage, Analytics or Crashlytics calls exist.

9. PERMISSIONS AND PRIVACY
--------------------------
The app uses explicit user-selected folder access rather than broad storage
manager permissions. The user controls which folder the app can access.

The app does not upload media. Original WhatsApp status files are read through
the authorized SAF tree and are not modified. Saved copies are written to the
user-selected destination or Android public MediaStore collections.

10. ICON AND SPLASH BRANDING
----------------------------
The complete Status Downloader logo is stored in the icon asset set. The active
native launcher/splash variants use the transparent-corner complete logo family,
not the white-background JPEG canvas.

Android launcher:
- Android density mipmap launcher images are present.
- Android adaptive icon XML points to the complete logo drawable.
- Background is supplied separately by the Android resource layer.

Android splash:
- Native launch resources reference the splash logo asset.
- The logo is not intended to be uploaded or fetched remotely.

If an Android launcher still shows an older image after reinstall/update, clear
launcher cache or uninstall/reinstall because Android launchers can cache icons.

11. IMPORTANT LIMITATIONS
-------------------------
- The project is Android-first; actual WhatsApp folder behavior requires a real
  Android device/emulator with WhatsApp media available.
- iOS contains icon/launch resources, but the WhatsApp SAF/MediaStore flow is an
  Android platform integration and is not equivalent on iOS.
- Local saved media is not protected against device loss unless the user/device
  backup system independently backs up the selected Gallery/folder location.
- Cache files are temporary and may be removed by Android.
